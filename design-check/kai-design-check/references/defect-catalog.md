# 결함 카탈로그 — 증상 → 원인 → 수정 → 검증

> 실제 프로젝트 두 곳(Angular 22 SSR 구매자웹 · Ionic 9 판매자앱)에서
> **재현하고 고친 것만** 적었다. 추측은 없다.
> 각 항목은 `증상`(사람 눈에 보이는 것) → `원인`(코드상 무엇) → `수정` → `검증`(계측기가 어떻게 잡는가) 순이다.

---

## A. 레이아웃 — 화면을 벗어남

### A1. 하단 고정 바가 데스크탑에서 오른쪽으로 넘침 🔴
| | |
|---|---|
| **증상** | 넓은 화면에서 "장바구니 담기" 같은 하단 바가 콘텐츠 폭을 벗어나 오른쪽으로 삐져나간다 |
| **원인** | 가운데 정렬을 `left:50% + transform:translateX(-50%)` 로 했는데, **같은 요소의 등장 애니메이션도 `transform` 을 쓴다.** `animation-fill-mode: both` 가 정렬용 transform 을 덮어써 바가 화면 중앙에서 시작한다 |
| **수정** | ```css\nposition: fixed; left: 0; right: 0; bottom: 0;\nwidth: min(100%, var(--app-col));\nmargin-inline: auto;\n``` |
| **검증** | `overflow-x` · `page-scroll-x` |

> 같은 함정: `sticky` + transform, 그리고 hover 로 `translateY` 를 주는 요소에 등장 애니메이션을 겹치는 것.

### A2. 좁은 폭(320px)에서 격자가 넘침
| | |
|---|---|
| **증상** | 320px 에서만 문서에 가로 스크롤이 생긴다 |
| **원인** | `grid-template-columns: repeat(auto-fit, minmax(320px, 1fr))` — **최소값이 남은 폭보다 크다** |
| **수정** | `minmax(min(320px, 100%), 1fr)` |
| **검증** | `overflow-x` @320 |

### A3. 격자 칸이 내용에 밀려 늘어남
| | |
|---|---|
| **증상** | `1fr 1fr` 인데 격자가 컨테이너보다 2~20px 넓다 |
| **원인** | 격자/플렉스 자식의 기본 `min-width: auto` — 내용이 칸보다 넓으면 칸이 늘어난다 |
| **수정** | `.grid > * { min-width: 0; }` (플렉스는 `min-width: 0` 또는 `overflow: hidden`) |
| **검증** | `overflow-x` |

### A4. 호스트에 상자가 없어 부모 스타일이 조용히 무시됨 🔴
| | |
|---|---|
| **증상** | `my-button { width: 100% }` 를 줬는데 버튼이 전폭이 아니다. **오류도 경고도 없다** |
| **원인** | 컴포넌트 호스트가 `display: contents` — 상자가 없으므로 폭·마진·정렬이 전부 무효 |
| **수정** | 호스트에 실제 display 를 준다. 전폭 변형은 별도 클래스로:<br>`:host { display: inline-flex; max-width: 100% }`<br>`:host(.full) { display: flex; width: 100% }` |
| **검증** | 눈으로는 안 잡힌다. `overlap` 과 화면별 폭 비교로 간접 발견 |

### A5. 플렉스가 눌러 글자를 자름
| | |
|---|---|
| **증상** | 금액·이름이 `₩3,80…` 처럼 잘린다 |
| **원인** | 형제가 폭을 다 먹어 글 칸이 눌렸다 |
| **수정** | 잘리면 안 되는 것에 `flex: none; white-space: nowrap`,<br>좁은 폭에서는 `flex-wrap: wrap` 으로 **아랫줄로 접는다**. 🔑 **금액·수량은 자르면 안 되는 정보다** |
| **검증** | `text-clip` |

## B. 가려짐 — 고정 요소 아래로 숨음

### B1. 마지막 내용이 하단 고정 바에 가림
| | |
|---|---|
| **증상** | 스크롤을 끝까지 내려도 마지막 버튼·글이 바에 덮여 안 보인다 |
| **원인** | `padding-bottom` 이 고정값인데, **좁은 폭에서 바가 두 줄로 접혀 높이가 커진다** |
| **수정** | `padding-bottom: calc(넉넉히 + env(safe-area-inset-bottom))`. 바 높이를 CSS 변수로 두고 공유하면 더 안전하다 |
| **검증** | `covered` — 본문 하단 여백 < 고정바 높이 |

### B2. 안전영역(노치·홈 인디케이터) 미반영
| | |
|---|---|
| **증상** | 실기기에서 하단 바가 홈 인디케이터에 잘리거나, 상단이 노치에 물린다 |
| **원인** | `env(safe-area-inset-*)` 를 안 썼다 |
| **수정** | 상단 `padding-top: env(safe-area-inset-top)`, 하단 `env(safe-area-inset-bottom)`.<br>Ionic 은 `--ion-safe-area-*` 변수를 함께 본다 |
| **검증** | 계측으로는 못 잡는다 — 실기기/시뮬레이터 필요 |

## C. 색 — 대비

### C1. 캡션·보조 문구가 AA 미달 🔴
| | |
|---|---|
| **증상** | 회색 작은 글씨가 읽기 힘들다 |
| **원인** | 디자인 시스템의 `--text-tertiary` 류가 애초에 3:1 대 |
| **수정** | 🔑 **위반이 어느 토큰에서 오는지 먼저 센다. 대개 토큰 2~3개가 90% 를 만든다.**<br>램프에서 **한 단씩** 내려 위계를 지키며 AA 를 넘긴다. 화면 코드는 손대지 않는다.<br>예: `secondary: ink-600→ink-700` · `tertiary: ink-500→ink-600` |
| **검증** | `contrast-aa` (4.5:1) · `contrast-hard` (3:1) |

### C2. 밝은 브랜드색 위의 흰 글자 🔴🔑
| | |
|---|---|
| **증상** | 주황·노랑 CTA 버튼의 흰 글자가 눈부시고 안 읽힌다 (3.36:1) |
| **원인** | 밝고 따뜻한 색은 **구조적으로 흰 글자를 못 받친다** |
| **수정** | 🔑 **채움색을 어둡게 하지 말고 글자를 어둡게 한다.**<br>`--action-accent-fg: 흰색 → ink-950` → 5.81:1.<br>**브랜드색이 그대로 살아 있으면서** AA 를 넘는다. 다크 테마에서는 채움을 한 단 밝게(ember-400) + 어두운 글자 → 7.13:1 |
| **검증** | `contrast-aa` |

### C3. 반전 카드의 제목이 사라짐 (대비 1.00:1)
| | |
|---|---|
| **증상** | 어두운 카드 위 제목이 **아예 안 보인다** |
| **원인** | 전역 `h1,h2,h3,h4 { color: var(--text-primary) }` 가 상속된 반전색을 덮어써 **글자색 = 배경색** |
| **수정** | `.on-inverse h1,.on-inverse h2,… { color: inherit; }` 전역 가드 |
| **검증** | `contrast-hard` — 1.00:1 이 나오면 이것이다 |

### C4. 어두운 뷰어 안에서 라이트 토큰이 그대로 쓰임
| | |
|---|---|
| **증상** | 이미지 뷰어(항상 검은 배경) 안의 캡션이 안 보인다 |
| **원인** | 화면 배경만 어둡게 하고 **글자 토큰은 라이트 값** 그대로 |
| **수정** | 그 화면 호스트에서 토큰을 지역 재정의: `:host { --text-tertiary: #A8A8B2 }` |
| **검증** | `contrast-hard` |

### C5. 테마 전환이 한쪽만 확인됨
| | |
|---|---|
| **증상** | 다크에서만 안 보이는 요소가 있다 |
| **원인** | 라이트만 보고 만들었다 |
| **수정** | 모든 계측을 **양쪽 테마에서** 돌린다. 색은 반드시 토큰으로 |
| **검증** | 계측기의 `themes` 를 2개 이상으로 |

## D. 터치 타깃 · 히트영역

### D1. 컨트롤이 22~28px
| | |
|---|---|
| **증상** | 체크박스·라디오·별점을 누르기 어렵다 |
| **원인** | 시각적 크기 = 히트영역 |
| **수정** | 🔑 **겉모습을 키우지 않는다.** `::after` 로 누를 면만 넓힌다:<br>```css\n.tap{position:relative}\n.tap::after{content:'';position:absolute;top:50%;left:50%;\n  width:max(100%,46px);height:max(100%,46px);transform:translate(-50%,-50%)}\n```<br>인접 컨트롤이 가까우면 **세로만**(`left:0;right:0`). 44 가 아니라 **46** 으로 한다 — 44 면 `elementFromPoint` 가 경계에서 놓친다 |
| **검증** | `tap-aa`(24px, WCAG 2.5.8) · `tap-touch`(44px, 2.5.5/HIG) |

### D2. 넓힌 히트영역이 이웃의 클릭을 가로챔 🔴
| | |
|---|---|
| **증상** | 버튼을 눌렀는데 옆 버튼이 눌린다 |
| **원인** | D1 의 부작용. `getBoundingClientRect` 로는 `::after` 가 안 보여 **겹침 검사에 안 잡힌다** |
| **수정** | 가로 확장을 세로 확장으로 바꾸거나, 간격을 늘린다 |
| **검증** | `tap-stolen` — 요소 중심을 `elementFromPoint` 로 눌러 **다른 상호작용 요소**가 잡히는지. ⚠️ 이 검사가 없으면 D1 을 적용하면 안 된다 |

### D2-b. 🔴 전역 터치 타깃 규칙이 엉뚱한 것을 부풀린다 (D1 을 잘못한 경우)
| | |
|---|---|
| **증상** | 스위치가 **거대한 알약**이 되고, 순서이동 화살표·텍스트 링크가 괴물처럼 커진다 |
| **원인** | `button, [role=button] { min-height: 44px }` 같은 **전역 규칙**이 스위치 트랙(28px)·화살표(22px)까지 잡는다 |
| **수정** | 🔑 **전역 규칙을 쓰지 않는다.** `::after` 로 **누를 면만** 넓히거나, 컴포넌트가 각자 크기를 책임진다 |
| **검증** | 눈으로 즉시 보인다. 계측기는 "크다"를 결함으로 세지 않으므로 **못 잡는다** |

### D3. 인라인 링크의 히트영역이 상하로 겹침
| | |
|---|---|
| **증상** | 목록 링크를 누르면 위/아래 항목이 눌린다 |
| **원인** | `<a>` 가 `inline` — **패딩이 줄 높이에 반영되지 않아** 패딩 상자끼리 포갠다 |
| **수정** | `display: block` (또는 `inline-block`) |
| **검증** | `overlap` |

### D4. 인풋의 실제 누를 면이 글자 높이뿐
| | |
|---|---|
| **증상** | 검색창 여백을 눌러도 포커스가 안 간다 |
| **원인** | 상자는 44px 인데 `<input>` 은 높이를 안 줘서 **23px**(글자 높이)만 차지 |
| **수정** | `input { align-self: stretch; height: 100%; }` |
| **검증** | `tap-aa` |

### D5. 라벨이 상자만 감쌈
| | |
|---|---|
| **증상** | 체크박스 글자를 눌러도 안 켜진다 / 글자 없는 체크박스가 22px |
| **원인** | 클릭 핸들러가 상자에만 있다 |
| **수정** | `<label>` 전체를 클릭 대상으로. 상자에 `tabindex="0"` + `keydown.space/enter`, `:focus-visible` 링 |
| **검증** | `tap-aa` — 라벨을 측정 대상으로 삼아야 정확하다 |

## E. 오버레이 (시트·모달·서랍·토스트)

### E1. 스크림이 뷰포트가 아니라 문서를 덮음 🔴
| | |
|---|---|
| **증상** | 긴 페이지 중간에서 시트를 열면 **화면 밖에** 뜬다 |
| **원인** | `position: absolute` |
| **수정** | `position: fixed` |
| **검증** | 오버레이 위치 감사 — `top > 화면높이` 또는 `bottom < 0` |

### E2. 접근성이 통째로 빠짐 🔴
| | |
|---|---|
| **증상** | 키보드로 오버레이를 벗어나거나, 스크린리더가 배경을 읽는다 |
| **원인** | 컴포넌트마다 따로 만들다 보니 어떤 것은 Escape 만 있고 나머지가 없다 |
| **수정** | 🔑 **공용 지시자/훅 하나로 모은다.** 넣을 것: `role=dialog`·`aria-modal`·접근 가능한 이름·**첫 포커스를 패널로**·Tab 가둠·Escape·**포커스 복원**·배경 스크롤 잠금 |
| **검증** | 오버레이 **행동** 감사 (위치 감사와 별개다) |

### E3. Escape 한 번에 겹친 오버레이가 함께 닫힘 🔴
| | |
|---|---|
| **증상** | 시트 위에 다이얼로그를 띄우고 Escape → **둘 다** 닫힌다 |
| **원인** | 컴포넌트마다 `document` 에 Escape 리스너를 달았다 |
| **수정** | 공용 스택을 두고 **맨 위 하나만** 처리. 지시자가 패널에 커스텀 이벤트를 쏘고 컴포넌트는 그것을 듣는다 |
| **검증** | 겹침 감사 — 2겹에서 Escape 후 남은 모달 수가 1인가 |

### E4. 배경 스크롤 잠금이 겹침에서 어긋남
| | |
|---|---|
| **증상** | 오버레이 하나를 닫자 나머지가 열려 있는데 배경이 스크롤된다 / 다 닫았는데 잠겨 있다 |
| **원인** | 잠금이 참조 카운트가 아니다. 증가는 렌더 후·감소는 파괴 시라 **비대칭** |
| **수정** | 스택/카운터 + **획득한 인스턴스만 해제**(`activated` 플래그) |
| **검증** | 겹침 감사 |

### E5. 스크롤바 보정이 본문을 밀어냄
| | |
|---|---|
| **증상** | 오버레이를 열면 뒤 화면이 살짝 옆으로 튄다 |
| **원인** | `body.style.paddingRight = gap` — **기존 padding 을 덮어썼다** |
| **수정** | computed 값에 **더한다**. 또는 `scrollbar-gutter: stable` 을 전역으로 |
| **검증** | 겹침 감사의 `padding-right` 잔여 확인 |

### E6. 닫은 뒤 포커스가 문서 맨 앞으로 떨어짐
| | |
|---|---|
| **증상** | 키보드 사용자가 시트를 닫으면 읽던 자리를 잃는다 |
| **원인** | 딥링크로 연 오버레이는 **여는 쪽(opener)이 없다** |
| **수정** | 부모 오버레이가 있으면 거기로, 없으면 **눈에 보이는 본문**에 `tabindex="-1"` 을 붙여 포커스.<br>⚠️ 포커스 준 뒤 `tabindex` 를 지우면 **그 순간 포커스가 풀린다** — 남겨 둔다(표준 skip-link 패턴) |
| **검증** | 행동 감사 |

### E8. 🔴 토스트·스피너를 **모달처럼** 다룸 (혹은 아무 표시도 안 줌)
| | |
|---|---|
| **증상** | 스크린리더 사용자가 "저장되었습니다" 토스트를 **듣지 못한다**. 로딩 중인지 모른다 |
| **원인** | 토스트·스피너는 모달이 아니라 **상태 알림**인데, ⓐ 아무 role 도 안 주거나 ⓑ 반대로 포커스를 가져간다 |
| **수정** | 토스트 `role="status"`(위험은 `alert`) + `aria-live="polite"`(위험은 `assertive`) + `aria-atomic`<br>스피너 `role="status"` + `aria-live="polite"` + `aria-busy="true"` + 이름<br>🔴 **포커스를 가져가지 않는다** — 작업 흐름이 끊긴다 |
| **검증** | 오버레이 a11y 감사에서 **모달과 갈래를 나눠** 검사해야 한다.<br>모달 기준(포커스 가둠·Escape)을 요구하면 **거짓 결함**이 난다 |

### E7. 오버레이 닫기가 history 를 쌓음
| | |
|---|---|
| **증상** | 시트를 닫고 뒤로가기를 누르면 **시트가 되살아난다** |
| **원인** | fragment/query 로 여닫으면서 `push` 로 닫았다 |
| **수정** | 닫을 때 `replaceUrl: true` (시트 간 전환도 마찬가지) |
| **검증** | 계측 어려움 — 규약으로 못 박고 리뷰에서 본다 |

## G. 애니메이션

### G1. `prefers-reduced-motion` 방어 부재 🔴
| | |
|---|---|
| **증상** | OS 에서 "동작 줄이기"를 켜도 화면이 계속 움직인다 |
| **원인** | 대응이 아예 없다 |
| **수정** | ```css\n@media (prefers-reduced-motion: reduce){\n *,*::before,*::after{\n  animation-duration:1ms!important;animation-delay:0ms!important;\n  animation-iteration-count:1!important;transition-duration:1ms!important;\n  scroll-behavior:auto!important}}\n```<br>🔴 **`animation: none` 으로 죽이면 안 된다** — `fill-mode: both` 인 요소가 `opacity:0` 에 영원히 갇힌다 |
| **검증** | 동작 줄이기 감사 — 숨은 요소 + **정책이 실제로 걸렸는지** (duration·iteration·transition·scroll-behavior 단언) |

### G2. `will-change` 상시 지정
| | |
|---|---|
| **증상** | 카드가 많은 화면에서 스크롤이 버벅이고 메모리를 먹는다 |
| **원인** | 공용 유틸에 `will-change: transform` 을 항상 켜 두어 레이어가 폭증 |
| **수정** | `@media (hover:hover){ .lift:hover{ will-change: transform } }` — 뜰 참에만 |
| **검증** | 계측으로는 못 잡는다 — 코드 검색 |

### G3. hover 효과가 터치 기기에서 붙어 버림

## H. SSR · 라우팅 (웹만)

### H1. 소프트 404
| | |
|---|---|
| **증상** | 없는 URL 이 200 을 준다 (SEO·모니터링에 해롭다) |
| **원인** | SPA fallback 이 전부 200 |
| **수정** | 알려진 경로 목록과 대조해 나머지는 404 |
| **검증** | `audit:routes` |

### H2. 프레임워크가 상태코드를 덮어씀 🔴
| | |
|---|---|
| **증상** | 404 를 지정했는데 200 이 나간다 |
| **원인** | Angular SSR 의 `writeResponseToNodeResponse` 가 `res.statusCode = response.status` 로 **덮어쓴다** |
| **수정** | `res.statusCode` 가 아니라 **`Response` 객체 자체**를 다시 만든다:<br>`new Response(response.body, { status: 404, headers: response.headers })` |
| **검증** | `curl -o /dev/null -w '%{http_code}'` |

### H3. `allowedHosts: []` 가 모든 요청을 400 으로 막음 🔴
| | |
|---|---|
| **증상** | 빌드된 SSR 서버가 `Header "host" … is not allowed` 로 **전부 400** |
| **원인** | `angular.json` 의 `security.allowedHosts` 가 빈 배열 |
| **수정** | 배포 도메인·localhost 를 넣는다 |
| **검증** | `audit:routes` — 이게 막혀 있으면 404 검사가 애초에 성립하지 않는다 |

### H4. 라우트 이중 관리 → 정상 페이지가 404
| | |
|---|---|
| **증상** | 화면은 잘 나오는데 HTTP 404 (소프트 404 의 반대) |
| **원인** | 앱 라우트와 서버의 "알려진 경로" 목록을 손으로 맞춰야 한다 |
| **수정** | 자동 검증을 건다 |
| **검증** | `audit:routes` — 화면 전수가 200 인가 |

### I0. 🔑 여백이 4px 모자란다 — **구조가 다른 것**이 원인
| | |
|---|---|
| **증상** | 합계 줄 위 여백이 48px 이어야 하는데 44px |
| **원인** | 레퍼런스는 **별도 1px div + `margin: 2px 0`**, 구현은 `padding-top + border-top`.<br>`10+2+1+2+10 ≈ 25px` vs `10+10+1 ≈ 21px` |
| **수정** | 계산된 값만 보지 말고 **레퍼런스 소스를 열어 구조를 본다** |
| **검증** | 레퍼런스 대조의 세로 간격. 같은 수정이 **여러 화면의 같은 편차**를 함께 해결한다 |

### I1. 열 폭이 화면마다 제각각

|---|---|
