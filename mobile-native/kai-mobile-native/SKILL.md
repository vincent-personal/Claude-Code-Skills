# kai-mobile-native — 모바일 네이티브 화면 개선

> 사용자가 다시 말하지 않아도 아래 **요구사항 전부**를 적용한다. 하나라도 어기면 완료가 아니다.
> 대화·보고는 한국어(사용자 호칭·말투는 전역 CLAUDE.md 규칙), 코드 영어, 주석 한국어.

## 0. 입력과 범위

| 호출 | 대상 |
|---|---|
| `/kai-mobile-native /members/list` (경로·화면 이름·컴포넌트 경로) | 그 화면 + 그 화면에서 열리는 숨은 부품(시트·서랍·다이얼로그·팝오버·토스트·빈 상태·오류 상태) |
| `/kai-mobile-native 전체` · "앱 전체" · "모든 화면" | 라우트 파일에서 **실제 사용 화면 전부**(준비 중·비활성 메뉴는 목록만 적고 보고에 "제외 사유") + 공용 틀(상단바·하단 탭·더보기·FAB) + 공개·로그인 화면 |
| 인자 없음 | 사용자에게 범위를 한 번만 묻는다 |

프로젝트가 따로 있으면 그 프로젝트의 CLAUDE.md·`docs/claude/*`(셸·오버레이·i18n 규약)를 **먼저 읽고** 그 규약 위에서 작업한다. 규약이 이 스킬과 충돌하면 사용자 최신 지시(이 스킬)가 우선이며, 충돌 사실과 바꾼 규약을 보고에 적고 규약 문서를 같이 고친다.

## 1. 사용자 요구사항 (원문 취지 — 전부 강제)

1. **네이티브 모바일 경험 최우선.** 데스크톱 반응형 축소처럼 보이면 실패. 전문가가 모바일 전용으로 설계·구현한 것처럼.
2. **공간을 잘 배치한다 — 빈 공간·불필요한 요소가 화면을 차지하지 않게.** 모바일은 화면이 한정되어 있으므로 각 기능마다 필요 없는 것(상시 안내 문구, 중복 제목, 넓은 아이콘 열, 큰 여백, 장식 카드)을 걷어 낸다.
3. **그리드·표·카드 배열을 "위치만 바꾸기"(열을 세로로 쌓기·순서만 바꾸기) 절대 금지.** 표현 자체를 모바일용으로 바꾼다(§4 패턴 표).
4. **다이얼로그 금지 — 정보가 많거나·스크롤되거나·입력 폼이 있는 화면은 가운데 모달로 띄우지 않는다.** 전체 화면 드로워 또는 바텀 시트. 가운데 다이얼로그는 확인창·짧은 알림만.
5. **주 행동은 엄지가 닿는 곳**: 만들기형 → 떠 있는 버튼(FAB), 편집·폼의 확정 → 하단 고정 액션 바, 보조 → 상단바 아이콘(최대 2) + ⋯ 시트.
6. **같은 줄 컨트롤 높이 동일**(1px 차이도 결함), 공용 버튼 컴포넌트만, 크기는 고정 높이로.
7. **터치 목표 44px 이상**(시각 크기가 작으면 터치 영역을 넓힌다), 하단 탭·홈 표시줄 안전 영역 고려.
8. **다국어·다크 모두에서 깨지지 않을 것** — ko·en·zh(简体) 원어민 문구, 길어지면 레이아웃이 아니라 더 짧은 원어민 표현으로.
9. **화면을 직접 측정·확인하고 판단**한다 — 코드만 보고 "됐다" 금지. 수치 측정이 기본, 모양 판단이 필요한 곳은 스크린샷(§2-1).
10. **🔴 모바일 웹 뷰에만 해당 — 데스크톱을 절대 망가뜨리지 않는다** (사용자 최강조). 모든 변경은 모바일 분기(폰·lg 미만 폭 신호, `max-lg:`/`lg:` 유틸, 모바일 전용 템플릿 분기) 안에서만. 데스크톱의 모양·위치·크기·동작(다이얼로그를 드로워로 바꾸기 포함)은 그대로 둔다. 공용 부품을 고칠 때는 데스크톱 경로가 바이트 단위로 같은 결과를 내는지 확인한다. 사용자가 데스크톱도 바꾸라고 **명시**할 때만 예외
11. **🔴 모바일 스크롤 = 화면 전체(문서·window) 스크롤 하나** (사용자 2026-10-22 "div 안에서 스크롤이 돌면 스크롤할 때 주소창이 자동으로 가려지는 이점을 누릴 수 없다"). 모바일 브라우저는 문서가 스크롤될 때만 주소창·하단 툴바를 접어 화면을 넓혀 준다.
    - 페이지 본문·목록·상세·**화면 전체를 덮는 레이어(전체 화면 드로워·전체 화면 다이얼로그·모바일 상세)** 모두 문서 스크롤로. `position:fixed` 패널 안 `overflow-y:auto` 본문이 화면을 꽉 채우는 구조 금지 — 전체 화면 레이어는 **흐름 안 페이지 레이어**(열리면 아래 페이지를 숨기고 레이어 내용이 문서를 스크롤, 닫으면 아래 페이지의 스크롤 위치 복원)로 만든다
    - 머리(✕·제목)·하단 바는 `position: sticky`(top/bottom)로 붙인다 — fixed 상자 안 스크롤로 흉내 내지 않는다
    - 예외(내부 스크롤 허용): 화면 일부만 덮는 **바텀 시트**(높이 ≤ 92dvh, 손잡이 있는 것), 팝오버·드롭다운 목록, 미리보기 기기 프레임 같은 "창 속 창"
    - 확인법: 375px에서 스크롤 시 `window.scrollY`가 변하고 스크롤 주체가 `document.scrollingElement`인지 실측(스크린샷과 함께), 전체 화면 레이어도 동일
    - 가로 스크롤 줄 스크롤바 숨김, 뒤로가기(안드로이드 백·iOS 스와이프)는 맨 위 겹침 한 겹만 닫힘.

12. **🔴 키보드는 용도에 맞게** (사용자 2026-10-22 "네이티브 모바일 키보드를 꺼낼 때 용도에 맞게"). 모든 입력 칸에 알맞은 `type`·`inputmode`·`enterkeyhint`·`autocomplete`·`autocapitalize`·`autocorrect`·`spellcheck`를 준다 — 데스크톱 모양에는 영향 없음:
    | 용도 | 속성 |
    |---|---|
    | 이메일 | `type="email" inputmode="email" autocomplete="email" autocapitalize="off" autocorrect="off" spellcheck="false"` |
    | 전화 | `type="tel" inputmode="tel" autocomplete="tel-national"`(국가 코드 칸 따로면) |
    | 정수(인원·순서·번호) | `inputmode="numeric" pattern="[0-9]*"` (`type="number"` 대신 — 스핀·스크롤 오입력 방지) |
    | 금액·소수 | `inputmode="decimal"` |
    | 검색 | `type="search" inputmode="search" enterkeyhint="search"` |
    | 주소·URL·slug | `type="url" inputmode="url"`(URL) / slug는 `autocapitalize="off" autocorrect="off" spellcheck="false"` |
    | 이름 | `autocomplete="name"`(또는 given-name·family-name) `autocapitalize="words"` |
    | 인증 코드(OTP) | `inputmode="numeric" autocomplete="one-time-code"` |
    | 비밀번호 | `type="password" autocomplete="current-password"`/`"new-password"` |
    | 우편번호·주소 | `autocomplete="postal-code"`·`"street-address"` 등 |
    | 메모·긴 글 | textarea `enterkeyhint="enter"`, 자동 고침 유지 |
    - `enterkeyhint`: 폼의 마지막 칸 = `done`/`send`(채팅)/`go`, 중간 칸 = `next`(다음 칸 이동 동작도 함께), 검색 = `search`
    - 날짜·시간은 커스텀 피커를 쓰면 입력 칸이 키보드를 띄우지 않게(`inputmode="none"` 또는 readonly 트리거) — 키보드와 피커가 겹치면 결함
    - 입력 글자 크기 16px 이상(iOS 포커스 자동 확대 방지)
    - 공용 입력 부품(전화·금액·검색·날짜)에 기본값으로 넣어 화면마다 반복하지 않는다
    - 확인법: 375 화면에서 각 칸의 속성 실측(가능하면 실기기 키보드 스크린샷), 체크리스트에 칸별 기록

## 2. 역할과 모델

- **상위 모델 = 페이블(Fable)** — 디자이너 검토·설계 판단 서브에이전트는 `model: "fable"`.
- 검토 3종(사용자 지정):
  - `design-critique`(디자인 플러그인) — 스크린샷의 사용성·위계·일관성 구조 평가 → **재설계 전** 진단
  - `design-review` — 디자이너 눈 QA·전후 스크린샷 다듬기 → **구현 후** 다듬기
  - `redesign-existing-projects` — 고급 품질 기준·흔한 AI 티 패턴 점검 → 재설계안 작성 시 기준
- `advisor` 서브에이전트 — 구조·규약·배선(누가 열고 누가 닫나) 자문. 스크린샷 파일 경로를 주면 이미지를 직접 본다.
- 교차 검증 — 프로젝트 규칙에 kai-openai 게이트가 있으면 구현 후 `kai_consult`.
- `kai-design-check`는 이 스킬에서 쓰지 않는다(사용자: 모바일에 맞지 않음).

## 2-1. ★ 토큰 예산 규칙 (사용자 지시 2026-10-23 — 전 절차에 우선)

실측(ChurchOn 콘솔 46화면 작업): 에이전트 290개·응답 3.9만 번·스크린샷 1,605장. 비용은 **응답 횟수 × 쌓인 대화 길이**에 비례한다. 매 응답이 그동안의 대화(이미지 포함)를 처음부터 다시 읽기 때문이다. 영역 에이전트 하나가 650~900번 응답하며 3억~5억 토큰을 썼고, 이미지를 찍은 에이전트가 전체의 37%를 차지했다. 아래를 지키지 않으면 같은 결과에 몇 배를 쓴다.

1. **에이전트 수명은 짧게.** 영역 에이전트 1명 = **화면 3~5개 또는 응답 약 150번**까지. 넘으면 진행 상황을 `.plan/mobile-native-{범위}.md`에 체크하고 끝낸다. 다음 묶음은 **새 에이전트**가 그 체크리스트와 요약만 받아 이어 간다. 한 에이전트가 한 영역을 끝까지 끌고 가지 않는다.
2. **측정 먼저, 사진은 마지막.**
   - 높이·폭·넘침·여백·스크롤 주체·터치 크기·키보드 속성은 `observe`(글자)와 `evaluate`(getBoundingClientRect·scrollWidth·getComputedStyle)로 수치를 뽑아 판정한다.
   - 스크린샷은 **모양을 눈으로 판단해야 할 때만** 찍는다.
   - 스크린샷 기본은 `size: small`이다. 작은 글자를 읽어야 하면 전체를 medium으로 찍지 말고 `screenshot_region`을 쓴다.
3. **촬영 조합 축소.**
   - 기본은 화면당 **ko 라이트 1장 + 다크 1장**(다크는 색·대비를 바꾼 화면만).
   - **en·zh는 문구·라벨 폭을 바꾼 화면만** 찍고, 그것도 넘침·줄바꿈 수치 측정이 우선이다.
   - 스크롤 끝까지 찍지 말고 바뀐 구간만 찍는다.
   - 숨은 부품은 **바꾼 것만** 연다.
4. **데스크톱 보호는 사진 대신 코드·DOM으로 증명.**
   - 모바일 분기 밖 diff가 0인지 본다(`git diff`에서 `max-lg:`·폰 분기 밖 변경 검사).
   - 1440 폭에서 대상 요소의 class·박스 수치를 Before와 After로 비교한다.
   - 데스크톱 스크린샷은 **공용 부품을 고쳤을 때만**, 대표 화면 1~2장만 찍는다.
5. **검토는 한 번, 묶어서.**
   - 디자이너와 advisor 진단은 **여러 화면을 한 번에** 받는다(이미지 경로 묶음, 화면당 1~2장).
   - After 재검토는 **🔴가 있던 화면만**, 최대 1회 받는다.
   - 🟡는 코디네이터가 판단해 반영하거나 차후로 넘긴다. "0이 될 때까지 반복" 금지.
   - `design-review` 다듬기는 전체가 아니라 사용자가 볼 대표 화면만 받는다.
6. **큰 파일은 필요한 줄만.** 1000줄 넘는 컴포넌트는 grep으로 위치를 찾고 `Read offset/limit`으로 읽는다. 통째로 읽지 않는다.
7. **모델 한도 대비.**
   - Fable 한도에 걸리면 같은 일을 새 에이전트로 되풀이하지 않는다. 즉시 Opus로 바꾸고, 앞 에이전트의 체크리스트 진행분부터 이어 간다.
   - 영역 에이전트(구현)는 Opus로 충분하다. Fable은 진단·설계 판단 1회에만 쓴다.
8. **병렬은 동시 2~3명.** 4명 이상은 코디네이터 맥락이 알림·인계로 빠르게 불어난다. 코디네이터는 에이전트 결과를 **요약 줄만** 받고, 긴 보고는 파일로 받는다.
9. **시험은 묶어서**(3-8). 수정 중에는 화면 측정으로 확인한다.

## 3. 절차

### 3-1. 목록 만들기 (전체일 때 필수, 단일 화면도 숨은 부품 목록)
- 라우트 파일·메뉴에서 화면 목록을 뽑고, 화면마다 숨은 부품(시트·서랍·다이얼로그·팝오버·빈 상태·오류·로딩)을 적는다.
- 산출: `.plan/mobile-native-{범위}.md` 체크리스트 — `- [ ] {경로} / {부품} : 상태`.

### 3-2. 현재 화면 촬영 (Before)
- **데스크톱 1440 Before 기록**: 대상 요소의 class·박스 수치를 남긴다(3-6 비교용). 사진은 공용 부품을 고칠 때만 대표 1~2장(§2-1-4).
- 브라우저 도구(Side X 등)로 **자기 탭**을 열고 `viewport 375×780`(필요하면 360·390·430도) — dev 서버는 사용자가 띄운 것을 쓴다(시작·종료 금지).
- 화면마다: 첫 화면 + 숨은 부품 목록 확인. 사진은 §2-1 규칙대로(기본 ko 1장, 다크·en·zh는 해당할 때만). 수치(observe·getBoundingClientRect)를 먼저 기록한다.
- 스크린샷 파일 경로를 기록(검토자에게 넘긴다).
- ⚠️ **폰 직접 진입(딥링크) 재현 순서**: 새 탭(about:blank) → viewport_set(폰 폭) → navigate. 넓은 폭에서 연 서랍·다이얼로그는 폭을 줄여도 데스크톱 방식(고정 패널·스크롤 잠금)으로 남는 것이 설계라, 순서를 바꾸면 "폰에서 스크롤이 안 된다" 같은 거짓 결함을 본다(2026-10-23 실제 오판)

### 3-3. 진단 (디자이너 + 자문 동시)
- 같은 턴에 병렬로:
  - 디자이너 검토 에이전트(`model: "fable"`, `design-critique` 스킬 사용 지시) — 스크린샷 경로 목록 + §1 요구사항 + §4 패턴 표를 주고 "네이티브 iOS/Android 관례 기준으로 결함과 재설계 방향을 화면별로" 요청
  - `advisor` — 같은 스크린샷 + 관련 소스 경로 — 구조·규약·공용 부품 재사용·배선 위험
- 결함 분류: 🔴 규칙 위반(§1) · 🟡 불편 · 🟢 다듬기. 화면별 재설계안을 체크리스트에 적는다.

### 3-4. 재설계 원칙 정하기 (공용 먼저)
- 공용 틀(상단바·하단 탭·더보기·FAB·하단 액션 바·시트/전체 화면 다이얼로그)이 요구사항을 못 맞추면 **공용부터** 고친다 — 화면마다 꼼수(`[iconOnly]="!isDesktop"` 류)를 만들지 않는다.
- 새 공용 컴포넌트가 필요하면 기존 것을 재사용할 수 없는 이유를 적고 진행(프로젝트 규칙상 승인 필요하면 사용자 보고에 명시).

### 3-5. 구현
- 단일 화면 = 직접. 전체 = 공용 틀 1명(직렬) → 영역별 에이전트 병렬(동시 4명 이하, 같은 파일 겹치지 않게 영역 분할, 공용 파일은 코디네이터만).
- 영역 에이전트에게 이 스킬 전체 + 자기 영역 체크리스트를 준다. **한 에이전트 = 화면 3~5개 묶음**(§2-1-1)이다. 끝나면 체크리스트를 갱신하고 종료하며, 다음 묶음은 새 에이전트가 맡는다. 동시 2~3명.
- 데스크톱 분기 변화 0 — 모바일 분기는 화면 폭 신호(프로젝트의 breakpoint 서비스)·`max-lg:`/`lg:` 유틸로.

### 3-6. 재촬영·재검토 (After)
- 바꾼 화면·바꾼 부품만 다시 측정하고, 모양 판단이 필요한 것만 찍는다(§2-1-2·3).
- **데스크톱 회귀 검사(필수)** — 머리말·버튼 위치·다이얼로그/드로워 종류·간격 변화가 하나라도 있으면 🔴(모바일 분기 밖으로 새어 나간 것). 증명은 다음 순서로 한다.
  - ① 모바일 분기 밖 diff 0.
  - ② 1440 폭에서 대상 요소 class·박스 수치를 Before와 비교해 일치하는지 본다.
  - ③ 공용 부품을 고쳤을 때만 대표 화면 1~2장을 찍어 나란히 비교한다.
- 같은 줄 컨트롤 높이는 `getBoundingClientRect`로 실측.
- 재검토는 **🔴가 있던 화면만, 묶어서 최대 1회** 받는다(디자이너 + advisor). 🟡는 코디네이터가 반영할지 차후로 넘길지 정한다(§2-1-5).

### 3-7. 다듬기
- `design-review` 스킬로 **대표 화면만**(영역당 1~2개) 간격·위계·정렬·AI 티 패턴을 다듬는다.

### 3-8. 시험·빌드·검사·교차 검증
- **시험은 묶어서** (사용자 2026-10-22): 고치는 동안에는 시험을 돌리지 않는다 — dev 서버 화면·스크린샷으로 확인. 한 영역(또는 한 묶음) 수정을 다 끝낸 뒤 그 영역 spec 1회, 커밋·배포 직전 전체 1회. 병렬 에이전트가 작업 중이면 그 완료 뒤에.
- 바꾼 화면 spec, 프로젝트 빌드, 프로젝트 검사 스크립트(예: check:buttons·fields·padding·scroll) 통과.
- 레이아웃 실측 spec이 있으면 모바일 기대값을 새 설계로 갱신(지우지 말 것).
- 교차 검증 게이트가 있으면 핵심 변경 요약으로 `kai_consult`.

### 3-9. 보고·저장
- 화면별 Before/After 요약(무엇을 걷어 냈고 무엇으로 바꿨나), 남은 실기기 확인 항목(iOS Safari 스와이프·안드로이드 키보드·안전 영역), 시험 결과.
- 새로 확정된 패턴은 프로젝트 규약 문서(`docs/claude/…`·CLAUDE.md)에 즉시 저장.
- 커밋은 사용자가 요청할 때. 새 디렉터리 staged 누락 확인.

## 5. 금지 목록 (보이면 🔴)
- 한 줄을 통째로 차지하고 한쪽이 비는 액션 줄
- 잘리는 화면 제목(상단바에 상주 컨트롤이 많아서)
- 같은 정보 두 번(제목 반복·부제에 탭 숫자 반복)
- 가운데 모달로 뜨는 폼·긴 정보
- 표·그리드를 세로로 쌓기만 한 것
- 데스크톱 패딩·간격·카드 크기 그대로(모바일에서)
- **모바일 작업이 데스크톱 화면을 바꾼 것**(모바일 분기 밖 변경 — 가장 중대한 결함)
- 두 줄로 접힌 버튼·placeholder·칩 라벨, 말줄임으로 뜻이 사라진 라벨
- 44px 미만 터치 목표, 엄지 닿지 않는 위치의 주 행동
- 내부 스크롤 이중화, 가로 넘침(문서 가로 스크롤)
- **화면을 꽉 채우는 레이어·페이지가 div 안에서 스크롤**(주소창이 접히지 않음 — 문서 스크롤로)
- 열자마자 포커스 테두리가 뜨는 버튼(초기 포커스는 패널·지정 요소에)
- 존재하지 않는 아이콘 이름(빈 아이콘) — 아이콘 세트에 실재하는지 확인
- **용도와 맞지 않는 키보드**(숫자 칸에 글자 키보드, 이메일 칸 자동 대문자, 검색 칸 엔터가 줄바꿈, 피커와 키보드가 동시에 뜸)
