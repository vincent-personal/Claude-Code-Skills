# kai-task-list — 미완료 작업 목록 조회 스킬

## 역할

`docs/check-list.md`를 읽어 **미완료 항목**만 추려서 사용자에게 보고한다.
코드 수정 없이 **읽기 전용**으로만 동작한다.

---

## ⚡ 실행 절차

### Step 0 — 프로젝트 루트 탐지

```bash
git rev-parse --show-toplevel 2>/dev/null || pwd
```

체크리스트 경로: `{PROJECT_ROOT}/docs/check-list.md`

파일이 존재하지 않으면 "아직 체크리스트가 없습니다. `/kai-task-add`로 첫 작업을 추가하세요." 보고 후 종료.

---

### Step 1 — 체크리스트 읽기

파일 전체를 Read한다.

---

### Step 2 — 상태별 항목 분류

항목을 아래 4가지 상태로 분류한다:

| 상태 | 마커 | 의미 |
|---|---|---|
| 미시작 | `- [ ]` | 아직 착수 전 |
| 진행중 | `- [~]` | 에이전트가 선점하여 작업 중 |
| 확인필요 | `- [!]` | 자체 판단 진행 후 사후 확인 권장 |
| 완료 | `- [x]` | 이미 완료 → **목록에서 제외** |

각 항목의 **첫 줄**(번호 + 요약 제목)과 **영향 파일** 항목만 추출한다.
세부 설명(3번째 줄 이후)은 생략한다.

---

### Step 3 — 요약 보고

아래 형식으로 출력한다.
항목이 없는 상태 그룹은 해당 섹션을 출력하지 않는다.

```
📋 미완료 작업 목록 — {PROJECT_ROOT 기준 프로젝트명}

🔵 미시작 (N개)
  #1 — 제목  [파일: foo.ts, bar.scss]
  #4 — 제목  [파일: baz.ts]

🟡 진행중 (N개)
  #2 — 제목  [파일: qux.ts]  (선점: YYYY-MM-DD HH:MM)

⚠️  확인필요 (N개)
  #3 — 제목  [파일: abc.ts]

✅ 완료 항목 수: N개 (상세는 /kai-task-clear 또는 check-list-done.md 참고)
```

모든 상태가 비어있으면:
```
✅ 미완료 작업이 없습니다. 모든 항목이 완료되었거나 체크리스트가 비어있습니다.
```

---

## Red Lines (절대 금지)

- ❌ 파일 수정·생성·삭제 행위 (읽기 전용 스킬)
- ❌ 체크박스 상태 변경
- ❌ 완료(`- [x]`) 항목을 목록에 포함시켜 혼동 유발
