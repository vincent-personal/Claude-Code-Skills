# 인터뷰 — 코드가 답할 수 있는 것은 절대 묻지 않는다

> 이 스킬이 실패하는 길은 하나뿐이다: **질문이 많아 다음 프로젝트에서 안 쓰게 되는 것.**
> 그러므로 **먼저 다 채워 놓고, 사람만 아는 6개만 묻는다.**

## A. 스스로 캐낼 것 (묻지 말 것)

| 항목 | 캐내는 곳 |
|---|---|
| 기술 스택·버전 | `package.json` · `*.csproj` · `pubspec.yaml` · `requirements.txt` · `Dockerfile` |
| 규모 | 소스 파일 수 · 엔드포인트 수(컨트롤러/라우트 grep) · 테이블 수(스키마·마이그레이션) · 화면 수 |
| 기능 목록 | 라우트 정의 · 컨트롤러 · 메뉴/내비 구성 |
| 아키텍처 | 진입점부터 데이터 저장소까지 **실제로 따라가며** 그린다 (추측 금지) |
| 배포 | `Dockerfile` · `compose.yml` · `fly.toml` · `railway.json` · CI 워크플로 · 배포 스킬 |
| 기간 | `git log` 첫 커밋 ~ 마지막 커밋 |
| **트레이드오프 후보** ★ | `CLAUDE.md` · `docs/` · `SESSION_HANDOFF.md` · ADR · **긴 커밋 메시지** — "왜 이렇게 했는가"가 적혀 있는 곳 |

★ 마지막 줄이 이 스킬의 값어치다. 대개 프로젝트 안에 **이미 "왜"가 적혀 있다.**

## B. 사람에게만 물을 것 (6개 — 이보다 늘리지 말 것)

초안을 **먼저 보여준 뒤** 한 번에 묻는다 (AskUserQuestion 1회).

1. **왜 시작했나** — 누구의 어떤 고통이었나. (가장 중요. 케이스 스터디의 첫 문단이 된다)
2. **내 역할** — 혼자인가, 팀이면 내 몫은 어디까지인가
3. **가장 어려웠던 고비 1~2개** — 무엇이 막았고 어떻게 넘었나
4. **결과 수치** — 있으면. 없으면 비운다
5. **공개 범위** — 고객명·로고·도메인·실데이터·스크린샷을 써도 되는가
6. **노리는 자리** — 어떤 일감·어떤 포지션을 겨냥하나 (글의 톤과 강조점이 여기서 갈린다)

## C. 무응답 기본값 (반드시 지킬 것)

| 미응답 항목 | 기본 처리 |
|---|---|
| 결과 수치 | **정성 결과만** 쓰고 숫자 자리에 `🔶` — 예: `Removed the manual step entirely (🔶 hours saved not measured)` |
| 공개 범위 | **익명화가 기본.** 프로젝트명을 일반명사로(`a church management portal`), 도메인·로고·실명·실데이터는 마스킹. 실명은 **명시 허락이 있을 때만** |
| 나머지 | 해당 절을 `🔶 확인필요` 로 남기고 **그대로 산출한다.** 미완이라도 남기는 것이 목적 |

## D. 재실행 (멱등)

`showcase/INTERVIEW.md` 가 이미 있으면 **읽어들이고, 바뀐 것만** 묻는다.
이것이 없으면 두 번째 실행 때 처음부터 다시 묻게 되어 — 이 스킬이 풀려던 문제로 되돌아간다.
