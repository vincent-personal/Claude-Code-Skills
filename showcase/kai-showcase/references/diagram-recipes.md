# 도면 두 벌 — 기술자용과 비전문가용

같은 시스템을 **두 번** 그린다. 독자가 다르면 그림도 달라야 한다.

## ① 기술 도면 (리크루터·개발자용)

**레인(세로 칸)으로 나눈다** — 예: 사용자 기기 / 우리 서버 / 외부 서비스 / 소비자.
- **위 절반 = 업스트림, 아래 절반 = 다운스트림**. 색을 둘로 갈라 방향을 보이게 한다
- **외부 서비스 레인은 짧게** 그린다 — 존재 구간이 한정됨이 눈에 보인다
- 화살표에 **실제 수치**를 적는다 (`Int16 PCM · 100 ms`, `MP3 64 kbps`). 무라벨 화살표는 "관련 있음"밖에 말하지 못한다
- 박스 이름이 아니라 **기제**를 그린다 — "캐시"가 아니라 요청이 지나는 경로
- 가드레일(인증·상한·타임아웃)은 박스가 아니라 **아래 콜아웃**으로 뺀다
- 도면 아래에 **제원표** + **설계 결정 3개**를 붙인다

## ② 비전문가 도면 (고객·일반 사용자용)

**기술 낱말을 하나도 쓰지 않는다.** 대신 *사람이 실제로 하는 동작*만 남긴다.
- **3단계**가 상한. 큰 세리프 번호 + 짧은 제목 + 화면 스케치 + 두세 문장
- 화면 스케치는 휴대폰 프레임 안에 **요소 2~3개만**
- **헤매기 쉬운 지점을 반드시 짚는다** — 예: "버튼이 회색이면 고장이 아니라 아직 시작 전"
- 아래에 "알아두면 좋은 것" 4개 (설치 필요 없음 / 늦게 와도 됨 / 소리 / 지연)

## 공통 규칙 (어기면 캡처가 흔들린다)

- **한국어는 `word-break: keep-all`** — 없으면 "앱 / 은 설치하지" 처럼 조사가 떨어진다 (실측)
- 라이트/다크 **토큰을 양쪽 다** 정의하고 `body` 배경을 명시한다
- 모든 `font-family` 에 **실제 폴백 스택**을 둔다 — 웹폰트가 늦으면 폴백으로 찍힌다
- 넓은 도면은 `overflow-x: auto` 컨테이너에 넣어 본문이 가로로 밀리지 않게 한다

## ③ 캐러셀 슬라이드 뼈대 (1080×1350 고정)

```html
<style>
  html, body { height: 100%; margin: 0; overflow: hidden; }   /* ★ 없으면 스크롤바·여백이 낀다 */
  .slide {
    width: 1080px; height: 1350px; box-sizing: border-box;
    padding: 96px 80px; display: flex; flex-direction: column; justify-content: space-between;
  }
  /* 글자는 크게 — 모바일 피드에서 읽힌다: 제목 64~80px, 본문 30~36px, 라벨 24~28px */
</style>
<div class="slide"> … </div>
```
장마다 **같은 레이아웃·같은 색**. 슬라이드 하나에 주장 하나.

## 캡처

```bash
CAP=~/.claude/skills/kai-showcase/assets/capture.sh

bash "$CAP" src/01-architecture.html assets/01-architecture.png            # 전체 페이지 + 트림
bash "$CAP" --batch src/linkedin --mode=fixed                              # 슬라이드 전부 (같은 이름 .png)
```

`capture.sh` 는 Artifact 스켈레톤 래퍼를 자동으로 씌우고, 다크모드·애니메이션·lazy 이미지를
고정한 뒤 찍는다. **HTML 은 조각(fragment)으로 쓴다** — `<html>`·`<body>` 를 직접 쓰지 않는다
(이미 완전한 문서라면 `--no-wrap`).

실측치 (2026-09-15): page 모드 ~8초 · fixed 모드 ~6초 · scale 2 에서 1080×1350 → **2160×2700**.
