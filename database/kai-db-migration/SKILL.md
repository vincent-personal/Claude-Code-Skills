# kai-db-migration — 데이터베이스 무손실 이전 (실측 증명 방식)

## 역할

DB 하나를 **완전 동일하게** 옮긴다. "옮긴 것 같다" 가 아니라 **숫자로 증명**하고 끝낸다.

이 스킬은 **실제로 깨져 본 이전**(2026-08-31 `AHAJA_BIBLE` Azure→Helsinki)에서
값을 치르고 얻은 것만 담았다. 추측으로 쓴 절차는 한 줄도 없다.

> **왜 스킬이 필요한가.** 지난 이전은 테이블 93개·행수 754,586 을 전수 대조해 "완벽" 이라
> 보고했으나 **앱이 붙자 깨졌다.** 원인은 `lower_case_table_names` 불일치였고, 사용자가
> 백엔드 코드를 손봐야 했다. **행수 대조는 완료의 증거가 아니다.**

## 발동

```
/kai-db-migration {어느 DB를 · 어디에서 · 어디로}
```

**명세가 부족하면 절대 추측하지 말고 사용자에게 묻는다** (GATE 0).

---

## ⚡ 실행 절차

### GATE 0 — 이전 명세 확정 (부족하면 **반드시 질문**)

아래 표를 **전부 채우기 전에는 아무것도 실행하지 않는다.** 빈칸이 하나라도 있으면
`AskUserQuestion` 으로 묻는다. **추측해서 채우지 않는다.**

| 항목 | 원본 | 대상 |
|---|---|---|
| 접속 주소·포트 | | |
| 엔진·버전 | | |
| **스키마명 (정확한 대소문자)** | | |
| 접속 계정 / 암호 **출처** | | |
| 컨테이너명·도커 네트워크 (해당 시) | — | |
| 대상에 같은 이름 스키마가 이미 있는가 | — | |

- [ ] 암호는 **값을 받아 적지 않는다.** *어디에 있는지*(컨테이너 env, `.env`, 시크릿 파일)만 확보
- [ ] 대상에 **동명 스키마가 이미 있으면 → 사용자 승인 없이는 진행 금지.** 덮어쓰기는 파괴적이다
- [ ] 이 DB 를 쓰는 **앱/백엔드가 무엇인지** 확인 (컷오버 대상 목록. GATE 8 에서 쓴다)

### GATE 1 — 양쪽 **실측** (읽기 전용. 추측 금지)

원본과 대상 **양쪽 모두** 잰다. 한쪽만 재면 불일치를 못 본다.

```bash
# 헬퍼 — 값 노출 없이 잰다
bash assets/mysql-inventory.sh <원본별칭>   > /tmp/src.inv
bash assets/mysql-inventory.sh <대상별칭>   > /tmp/dst.inv
diff -u /tmp/src.inv /tmp/dst.inv | head -40
```

수동으로 잴 때 최소 항목:

```sql
SELECT VERSION()                    AS version,
       @@lower_case_table_names     AS lcs,      -- 🔴 가장 중요
       @@character_set_server, @@collation_server,
       @@sql_mode, @@default_storage_engine,
       @@time_zone, @@system_time_zone, @@max_allowed_packet;
```

- [ ] 버전 (원본 → 대상 **상위 버전이면 제거된 기능**이 있다. GATE 5)
- [ ] **`lower_case_table_names`** ← GATE 2 의 입력
- [ ] 서버 charset / collation
- [ ] `sql_mode` (`ONLY_FULL_GROUP_BY` 등이 다르면 **기존 쿼리가 런타임에 깨진다**)
- [ ] 대상 **디스크 여유** ≥ 덤프 크기 × 3 (덤프 + 복원 중 InnoDB + 여유)
- [ ] 원본 → 대상 **네트워크 도달 가능**한가 (덤프를 어디서 뽑을지 결정)

**🚦 게이트: 원본·대상 실측값을 표로 사용자에게 보고한다.**

---

### GATE 2 — 🔴 대소문자 판정 (이 스킬의 핵심. 건너뛰면 반드시 깨진다)

`lower_case_table_names`(이하 `lcs`)는 **데이터 디렉터리를 처음 만들 때만 정할 수 있고
나중에 바꿀 수 없다.** Windows 기본값은 `1`, Linux 기본값은 `0` 이다.

| 원본 `lcs` | 대상 `lcs` | 결과 |
|---|---|---|
| 1 | 1 | ✅ 안전 |
| 0 | 0 | ✅ 안전 |
| **1** | **0** | 🔴 **원본은 이름을 소문자로 저장·대소문자 무시 비교. 대상은 구분.**<br>Windows 에서 멀쩡하던 쿼리가 `table doesn't exist` 로 깨진다 |
| **0** | **1** | 🔴 원본에 대소문자가 다른 동명 테이블이 있으면 **복원 자체가 충돌** |

- [ ] `lcs` 가 **같으면** → 통과. 그래도 GATE 7 에서 **테이블명 문자열을 1:1 대조**한다
- [ ] `lcs` 가 **다르면** → 아래 셋 중 하나를 **사용자에게 물어 고른다.** 임의로 진행 금지

| 선택지 | 내용 | 대가 |
|---|---|---|
| **A. 대상을 원본에 맞춘다** | 대상 DB 인스턴스를 **원본과 같은 `lcs` 로 재초기화** (`--lower-case-table-names=N`) | 데이터 디렉터리를 비워야 한다. ⚠️ **대상이 다른 스키마를 이미 담고 있으면 불가** |
| **B. 전용 인스턴스를 새로 띄운다** | 공유 컨테이너를 건드리지 않고 **원본과 같은 `lcs` 의 인스턴스**를 따로 기동 | 메모리·포트·백업 대상이 하나 늘어난다 |
| **C. 불일치를 감수한다** | 그대로 옮기고 **앱 코드에서 대소문자를 맞춘다** | 🔴 **백엔드 수정이 반드시 필요하다.** 사용자에게 명시적 동의를 받고 문서에 남긴다 |

> ⚠️ **대상이 이미 운영 중인 공유 인스턴스면 A 는 불가능하다.** 다른 스키마가 함께 죽는다.
> 이 경우 B 또는 C 이며, **C 를 고를 때는 "백엔드 코드 수정이 필요함" 을 먼저 통보**한다.
> 지난번 실패는 **이 통보를 이전이 끝난 뒤에야 한 것**이 문제였다.

- [ ] 결정과 근거를 **문서에 적는다** (다음 사람이 다시 조사하지 않도록)

### GATE 3 — 사전 인벤토리 (덤프 **전**에 원본 기준선을 고정한다)

```bash
bash assets/mysql-objects.sh   <원본별칭> <DB> > /tmp/src.objects
bash assets/mysql-rowcount.sh  <원본별칭> <DB> > /tmp/src.rowcount
```

- [ ] **객체 수를 종류별로** 센다 — 테이블 · 뷰 · **프로시저** · **함수** · **트리거** · **이벤트** ·
      외래키 · 인덱스
      > ⚠️ **프로시저와 함수는 따로 센다.** `information_schema.ROUTINES` 에 섞여 있어
      > 한 번에 세면 함수 누락을 못 본다
- [ ] **행수는 `information_schema` 추정치를 쓰지 않는다.** InnoDB 추정치는 틀린다.
      **전 테이블에 `count(*)` 를 실제로 돌린다**
- [ ] **DEFINER 목록**을 뽑는다 — 뷰·프로시저·함수·트리거·이벤트
      > ⚠️ 덤프는 `DEFINER='user'@'host'` 를 그대로 담는다. 대상에 그 계정이 없으면
      > 객체는 만들어져도 **실행 시점에 권한 오류**가 난다
- [ ] 원본 사용자·권한(`SHOW GRANTS`)과 **인증 플러그인**을 기록

### GATE 4 — 덤프

```bash
mysqldump --databases "$DB" \
  --routines --triggers --events \
  --single-transaction --quick --set-gtid-purged=OFF \
  --default-character-set=utf8mb4 --hex-blob \
  --column-statistics=0 --no-tablespaces \
  > "$WORK/$DB.sql"
```

| 플래그 | 없으면 |
|---|---|
| `--routines` | **프로시저·함수가 통째로 사라진다** |
| `--triggers` | 트리거 소실 (기본 on 이나 **명시한다**) |
| `--events` | **스케줄 이벤트가 조용히 사라진다** — 나중에 "배치가 안 돈다" 로 발견된다 |
| `--single-transaction` | 덤프 중 쓰기와 섞여 **시점 불일치**. ⚠️ InnoDB 전용 — MyISAM 이 섞였으면 `--lock-tables` |
| `--hex-blob` | 바이너리 컬럼 깨짐 |
| `--set-gtid-purged=OFF` | 대상에서 GTID 충돌 |
| `--column-statistics=0` | 8.0 클라이언트가 구버전 서버를 덤프할 때 오류 |

- [ ] 덤프 **직후 크기와 `tail`** 을 확인한다 — 정상 종료면 끝에 `Dump completed` 가 있다
      > ⚠️ 중간에 끊긴 덤프도 파일은 남는다. **크기만 보고 성공으로 치지 않는다**
- [ ] 원본을 **건드리지 않았음**을 확인 (덤프는 읽기 전용 작업이다)

---

### GATE 5 — 비호환 교정 (**고친 것을 전부 기록**)

교정 전 원본 덤프를 **`.orig` 로 보존한다.** 무엇을 왜 고쳤는지 남기지 않으면 나중에 추적 불가다.

```bash
cp "$WORK/$DB.sql" "$WORK/$DB.sql.orig"
```

**실제로 겪은 비호환** (상세: `references/mysql-traps.md`)

- [ ] **`mysql_native_password`** — MySQL 8.4 에서 **제거**되었다. 이 플러그인을 쓰던 계정은
      그대로 옮기면 **접속 자체가 안 된다** → 대상에 `caching_sha2_password` 계정을 새로 만든다
- [ ] **유일하지 않은 컬럼을 참조하는 외래키** — 8.0 은 허용했으나 **8.4 는 거부**한다.
      부모 컬럼에 UNIQUE 가 없으면 제약 생성이 실패한다
      → 값 분포를 조사해 UNIQUE 승격이 **가능한지 먼저 확인**하고, 불가능하면
        **`CONSTRAINT` 줄만 제거하고 `KEY` 인덱스는 남긴다** (조회 성능 유지)
      → **몇 건을 왜 제외했는지 반드시 보고**한다. 조용히 빼면 안 된다
- [ ] **DEFINER** — 대상에 없는 계정이면 계정을 만들거나 DEFINER 를 치환
- [ ] `utf8mb3` · 제거된 `sql_mode` 값 · 예약어가 된 식별자

### GATE 6 — 복원

- [ ] 대상 스키마가 **비어 있는지** 확인 (있으면 GATE 0 의 승인 사항)
- [ ] 복원은 **로그를 파일로 남기며** 돌린다. 화면만 보면 경고를 놓친다

```bash
docker exec -i <컨테이너> sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD"' \
  < "$WORK/$DB.sql" 2> "$WORK/log/restore.log"
```

- [ ] **`restore.log` 를 끝까지 읽는다.** `ERROR` 가 하나라도 있으면 **완료가 아니다**
- [ ] 대용량이면 `max_allowed_packet` · `innodb_buffer_pool_size` 를 먼저 확인

### GATE 7 — 🔴 검증 (3층 전부 통과해야 완료다)

**행수만 맞으면 완료라고 보고하지 않는다.** 지난번 실패의 정확한 지점이다.

**7-1. 객체 수 — 종류별로**

```bash
bash assets/mysql-objects.sh <대상별칭> <DB> > /tmp/dst.objects
diff -u /tmp/src.objects /tmp/dst.objects     # 차이 0 이어야 통과
```

- [ ] 테이블 · 뷰 · **프로시저** · **함수** · **트리거** · **이벤트** · 외래키 · 인덱스
- [ ] **이름 문자열까지 대조**한다 (개수만 맞고 이름이 다를 수 있다 — 대소문자!)

**7-2. 전 테이블 행수 — 실제 `count(*)`**

```bash
bash assets/mysql-rowcount.sh <대상별칭> <DB> > /tmp/dst.rowcount
diff -u /tmp/src.rowcount /tmp/dst.rowcount   # 차이 0 이어야 통과
```

**7-3. 🔴 실접속 — 앱이 실제로 붙어 쿼리가 도는가**

- [ ] **앱이 붙을 그 경로 그대로** 접속한다 (도커 네트워크 내부 이름 · 그 계정 · 그 암호)
- [ ] 대표 테이블 조회 + **프로시저 1개 실제 호출** + 뷰 1개 조회
- [ ] ⚠️ **이 단계 없이는 완료 보고 금지.** 행수·객체 수가 다 맞아도 여기서 깨진 전례가 있다

---

### GATE 8 — 접속 인계

- [ ] **전용 계정**을 만든다 (root 를 앱에 주지 않는다). 인증은 `caching_sha2_password`
- [ ] 연결 문자열을 사용자에게 전달 — **암호는 값 대신 보관 위치**를 알린다
- [ ] 포트를 **외부에 열지 않는다.** 외부 도구는 SSH 터널 경유
- [ ] 이전 결과 문서를 남긴다 (원본/대상 · 객체 표 · 행수 · **제외·변경한 것** · 접속 정보)

---

### GATE 9 — 원본 정리 (⚠️ 서두르지 말 것)

- [ ] **백엔드 전환·검증이 끝날 때까지 원본을 살려 둔다.** 되돌릴 유일한 경로다
- [ ] 원본 포트가 **인터넷에 열려 있었다면 이전 후 반드시 차단**한다
- [ ] 이 DB 를 쓰는 **모든 경로**(백엔드·모바일·배치·리포트)가 전환됐는지 확인 후 정리

## Red Lines (절대 금지)

1. ❌ **재지 않은 값으로 진행하기.** `lcs`·버전·collation 은 **추측 대상이 아니다**
2. ❌ **`lcs` 불일치를 조용히 넘기기.** 앱이 깨진다. 반드시 사용자 결정을 받는다
3. ❌ **행수 일치만으로 "완벽하게 옮겼다" 보고하기.** 실접속(7-3)이 빠지면 미완이다
4. ❌ **암호를 명령줄 `-p` 에 붙이기** — 프로세스 목록에 노출된다. `MYSQL_PWD` 나 옵션 파일을 쓴다
5. ❌ **암호를 출력·로그·커밋·문서에 남기기.** 문서에는 *보관 위치*만 적는다
6. ❌ **`.orig` 없이 덤프 수정하기**, 그리고 **제외한 객체를 보고하지 않기**
7. ❌ **대상의 기존 스키마를 승인 없이 DROP·덮어쓰기**
8. ❌ **원본을 즉시 삭제하기.** 백엔드 검증 완료까지 유지
9. ❌ **`--routines --triggers --events` 중 하나라도 빠뜨리기**
